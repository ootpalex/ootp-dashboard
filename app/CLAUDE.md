# SSB GM Dashboard

## Project Overview
React SPA dashboard for managing an OOTP (Out of the Park Baseball) online league. Replaces complex Excel spreadsheets (~85MB) with an interactive web tool for draft preparation, free agent analysis, prospect tracking, and organizational assessment.

## Tech Stack
- **React 18** with Vite
- **No backend** — everything runs in browser
- **Data**: Per-league JSON dashboards under `public/data/<slug>/dashboard.json.gz` with a `public/data/leagues.json` registry, auto-loaded on startup. Falls back to legacy single-league `public/data/dashboard.json.gz` (no index) and finally to manual file upload.
- **Styling**: Inline styles (dark theme, monospace font)
- **State**: React hooks + localStorage for team and game date persistence
- **Charts**: Recharts (scatter plots, line charts, composed charts)
- **External API**: StatsPlus API URL configurable via League Settings (default: `https://atl-01.statsplus.net/ssb/api`), proxied via Vite dev server to avoid CORS

## Data Architecture

### Source Format
Data is served as one gzipped JSON file per league at `public/data/<slug>/dashboard.json.gz`, plus a `public/data/leagues.json` registry that the SPA reads first to discover available leagues. Both are generated by the Python pipeline at `model/`. The JSON contains nested player objects — **not flat CSV columns**. See the **Multi-League Architecture** section below for the registry shape and fetch flow.

### JSON Player Structure
Each player object has nested groups instead of flat columns:
```
{
  meta: { name, pos, org, lev, bats, throws, prone, price, proy, mld, oy, opt, int, we, ad, dem, stm, velo, ovr, pot, on40, r5, manual, ... },
  batting: { vR: { obp, woba, batR, ... }, vL: { ... }, wtd: { ... } },
  baserunning: { vR: { bsr, ... }, vL: { ... }, wtd: { ... } },
  positions: { c: { eligible, waa: { vR, vL, wtd }, stats: { runsP, ... } }, "1b": { ... }, ... },
  maxWaa: { vR, vL, wtd },
  maxWar: { vR, vL, wtd },          // post-v0.2.0: parallel WAR fields throughout
  sp: { vR: { waa, ... }, vL: { ... }, wtd: { ... } },
  rp: { vR: { waa, ... }, vL: { ... }, wtd: { ... } },
  prospect: { waa: { max, c, "1b", ..., sp, rp }, sp: { waa }, rp: { waa } },
  starter: bool, starterP: bool,
  ID, _uid, ...
}
```

### Accessor Helpers (nested JSON with CSV fallback)
All data access should use these helpers — **never access flat column names directly**:
- `getWar(p, pos, split)` / `getWarP(p, pos)` — Position WAR / potential WAR (post-v0.2.0 default value metric)
- `getMaxWar(p, split)` / `getMaxWarP(p)` — Best WAR / potential WAR across eligible positions
- `getSpWar(p, split)` / `getRpWar(p, split)` — SP/RP WAR
- `getSpWarP(p)` / `getRpWarP(p)` — SP/RP potential WAR
- `getFloorWar(p, split)` / `getSpFloorWar(p)` / `getRpFloorWar(p)` — Floor WAR (developable-rating min)
- `getWaa*` family (`getWaa`, `getMaxWaa`, `getSpWaa`, `getRpWaa`, etc.) — **Preserved but unused.** Pipeline still emits WAA columns alongside WAR in `dashboard.json`; the WAA accessors remain available for a future "show WAA" toggle. Don't introduce new WAA-only views.
- `getRunsP(p, pos)` — Defensive runs saved
- `isEligible(p, pos)` — Position eligibility boolean
- `getBatR(p, split)` — Batting runs
- `getBsr(p, split)` — Baserunning runs
- `resolveKey(p, key)` — Maps flat column-name keys (used in column definitions) to nested JSON values. Single choke-point for sort/render code. Handles both `"Max WAR wtd"` and the legacy `"Max WAA wtd"` keys.

### Key Meta Fields
- **ID**: Player identifier, links to StatsPlus API
- **meta.org**: Team ownership (28 teams, "-" = free agent)
- **meta.lev**: Level — MLB, AAA, AA, A+, A, R (Rookie), INT (International)
- **meta.manual**: Multi-purpose tag — "IAFA", "DRAFT", "2042 Draft", "Draft 2043", etc.
- **meta.pos**: Primary position
- **meta.dob**: Date of birth in YYYY-MM-DD format (used for exact age calculation with game date)
- **meta.on40**: Boolean — on the 40-man roster
- **meta.r5**: Boolean — Rule 5 draft eligible
- **meta.prone**: Injury proneness (Iron Man, Durable, Normal, Fragile, Wrecked)
- **meta.int/we/ad**: Intangibles (H/N/L)
- **meta.stm/velo**: Pitcher stamina and velocity
- **meta.salary**: Parsed numeric salary from OOTP SLR column
- **meta.price**: Computed price (max of salary, league min; demand for unsigned FAs)
- **meta.mld**: MLB service days (years × 172 + days)
- **meta.yl**: Years left string (e.g. "1 (auto.)", "3 (Club Option)", "1 (arbitr.)")
- **meta.opt**: Options remaining (0-3)
- **meta.act**: Boolean — on active roster
- **meta.ic**: Injured list status ("-" when healthy)
- **meta.proy**: Professional years (total years in organized baseball)
- **meta.draft**: Draft year (0 if undrafted)
- **meta.oy**: Option years
- **meta.cv**: Contract value (total)
- **meta.ty**: Total years on contract
- **meta.ecv**: Extension contract value
- **meta.ety**: Extension total years
- **meta.secy/meta.secd**: Secondary service years/days
- **meta.dfa**: DFA status
- **meta.rook**: Boolean — rookie status
- **meta.mlb_service_days_this_year**: MLB service days accrued in the current season (from StatsPlus `/players`). Used by the Super-Two filter to enforce the ≥86-day rule.
- **meta.is_on_dl** / **meta.is_on_dl60**: 15-day / 60-day IL flags from StatsPlus `/players`
- **contract**: StatsPlus year-by-year contract data (when pipeline fetched from API):
  - `salaries`: Array of per-year salary amounts
  - `years`, `currentYear`, `seasonYear`
  - `lastYearTeamOption/PlayerOption/VestingOption`: Option flags
  - `nextLastYearTeamOption/PlayerOption/VestingOption`: Penultimate year options
  - `lastYearOptionBuyout`, `nextLastYearOptionBuyout`: Buyout amounts
  - `noTrade`: No-trade clause
  - `extension`: Nested contract object (same shape) for extension deals

### Computed Fields (added in processData / Dashboard)
- **`_age`**: Initially from JSON `meta.age`. When game date is set in sidebar, recomputed as exact fractional age from `meta.dob` via `recomputeAges()`. All views receive the recomputed data.
- **`_bestPos`**: Computed in `processData()` via `calcBestPos()`:
  - **Hitters**: Position with highest RunsP (via `getRunsP()`) among eligible positions (via `isEligible()`). Falls back to `meta.pos`.
  - **Pitchers**: Compares SP WAA vs RP WAA (via `getSpWaa()`/`getRpWaa()`). Shows `RP*` when best is RP but player is SP-eligible (`starter` or `starterP`).
- **`_type`**: "hitter" or "pitcher"
- **`_price`**: Parsed numeric salary from `meta.price`

### Filtered Out
- Auto-detected teams with player counts below 25% of league average (configurable via League Settings exclusion overrides)
- Empty rows (ORG = "" or "0")

## Multi-League Architecture

The SPA supports multiple leagues from a single deploy. Each league has its own dashboard JSON; localStorage state is per-league for most keys (so switching leagues swaps team selection, game date, roster plans, etc.) and global for a few (curve settings, the active-league pointer itself).

### Registry: `public/data/leagues.json`
```json
{
  "leagues": [
    {
      "slug": "default",
      "leagueName": "Default League",
      "ootpVersion": "26",
      "team": "Atlanta Braves",
      "dashboardPath": "default/dashboard.json.gz",
      "lastBuilt": "2026-04-30T04:00:46.809129+00:00"
    }
  ]
}
```
Maintained by `model/main.py:_update_leagues_index()` after every pipeline run.

### App.jsx fetch sequence
1. Try `GET /data/leagues.json`. If absent or invalid → `leagues = []` (legacy mode).
2. Resolve `activeSlug`: prefer the persisted `currentLeague` from `localStorage["ssb_current_league"]` if it appears in the registry; otherwise fall back to the first league's slug. If the resolved slug differs from what was persisted, write the resolved value back.
3. Fetch the dashboard:
   - Multi-league: `GET /data/<activeSlug>/dashboard.json`
   - Legacy fallback (no `leagues.json`): `GET /data/dashboard.json`
4. The fetch effect depends on `currentLeague`, so changing leagues from the sidebar selector triggers a fresh fetch + reprocess.
5. App wraps `<Dashboard>` in `<LeagueSlugContext.Provider value={activeSlug}>` and passes `leagues`, `currentLeague`, and `onSelectLeague` (which is just `setCurrentLeague`).

### Sidebar league selector
`Dashboard.jsx` renders a `<select>` of available leagues only when `leagues.length > 1`. Each option shows `"<leagueName> (OOTP <ootpVersion>)"`. Selecting a league calls `onSelectLeague(slug)` which updates the persisted `ssb_current_league` and re-fires the App.jsx fetch effect.

### Scoped storage helpers (`app/src/hooks/useLocalStorage.js`)
- `LeagueSlugContext` — React context, default `null`. Provided by App.jsx, consumed by `useScopedLocalStorage`.
- `keyFor(slug, baseKey)` — Returns `"baseKey::slug"` when slug is truthy, otherwise the bare `baseKey`. The single source of namespacing.
- `getCurrentSlug()` — Reads `ssb_current_league` directly from localStorage. Used by code that runs outside the React tree (e.g. `loadLeagueSettings`) and can't read context.
- `readScoped(baseKey)` / `writeScoped(baseKey, value)` — Non-hook variants. `readScoped` falls back to the legacy unscoped key if the scoped slot is empty (one-time hoisting). `writeScoped` always writes to the scoped key, never overwriting the legacy slot.
- `useScopedLocalStorage(baseKey, defaultValue, options)` — Hook variant. Same legacy-hoist initialization. `options.serialize` / `options.deserialize` allow non-string state (e.g. RosterPlanner uses it for the numeric R5 threshold).
- **Legacy hoisting**: when a scoped slot is empty but the unscoped legacy key exists, the legacy value is silently hoisted into the scope on first read. The legacy key is **deliberately not cleared** so that *other* leagues can also hoist from it. This makes a v0.0.x → v0.1.0 upgrade seamless: pre-multi-league localStorage is preserved as a "default" template each new league inherits.

### Per-league storage scope reference

| Key | Scope | Owner |
|---|---|---|
| `ssb_current_league` | Global | App.jsx (`useLocalStorage`) |
| `ssb_dev_curve_settings` | Global | Dashboard, DevAnalysisView (shared across leagues by design — curve tuning is universal) |

When adding new persisted state, default to **per-league** (use `useScopedLocalStorage` or `readScoped`/`writeScoped`). Reach for global storage only when the setting is genuinely league-independent (curve tuning is the canonical example).

### Pipeline → frontend handshake
`model/main.py:247-266` writes both `dashboard.json.gz` (compressed) and `dashboard.json` (uncompressed) to `app/public/data/<slug>/`, then calls `_update_leagues_index(app_data_dir)` (defined at `model/main.py:66-95`) to refresh the registry. In legacy single-league mode (no `LeagueConfig`), the files go directly to `app/public/data/` and `leagues.json` is not written.

## Positional Strength Algorithm

### Defensive Spectrum Order (hardest -> easiest)
C -> SS -> CF -> 2B -> 3B -> LF -> RF -> 1B -> DH

### Current Mode (two-pass cascade)
1. Pass 1: Claim top 1 player at each position down the spectrum (starters first)
2. Pass 2: Go back through spectrum, fill remaining depth slots
3. Each player counted exactly once

### Potential Mode (single-pass)
1. Fill full depth at each position before moving to next
2. No DH position
3. SP: 10, RP: 8 (increased pitcher depth)
4. SP filled first, RP from non-SP eligible pitchers

### Depth Counts
- Current: C:4, 1B:3, 2B:3, 3B:3, SS:3, LF:3, CF:3, RF:3, DH:2, SP:8, RP:6
- Potential: C:4, 1B:3, 2B:3, 3B:3, SS:3, LF:3, CF:3, RF:3, SP:10, RP:8 (no DH)

### Player Assignment Helper
`assignPlayersToPositions(hitters, pitchers, depthMap, mode, waaColFn)` — Reusable cascade algorithm that returns `{ assigned: { [position]: Player[] }, unassigned: Player[] }` with actual player objects. Optional `waaColFn` overrides the WAA column accessor (used for platoon splits: `{POS} WAA vR` / `{POS} WAA vL`).

### Defensive Position Optimization
`optimizeDefensivePositions(starters, positions)` — After the WAR cascade picks the best 9 players, this function reassigns them to positions to maximize total defensive runs saved (`{POS} RunsP` columns), respecting `{POS} Eligible` flags. Greedy assignment along the defensive spectrum (hardest positions filled first). Applied to Active Roster starters, 40-Man starters, and Optimized Lineup.

## Smart Rank System (Draft Board + IAFA Board)
Four stackable toggles:
1. **Org Positional Need** — Inverts org z-scores: weak positions get higher multiplier
2. **Positional Scarcity (VBD)** — Measures talent drop-off per position in remaining pool
3. **Future Value** — Risk-adjusted future value rating using power-law current/potential blend with development percentile risk discount
4. **Defensive Spectrum Premium** — Flat bonuses for C/SS/CF, penalties for 1B/DH

### v21 — Three-input simplification with power-law creditAge
**FV = cur + gap × creditAge.** Drops devPct from the formula entirely. Pot is reframed as the *ceiling* (max valuation at maturity) — `(cur, pot, age)` already encode the relevant per-player spread, so within-cohort discrimination via batR-pct is unnecessary. `creditAge` uses a smooth power-law decay from `gapMax` at age 14 to 0 at maturity.

**Migration history**: v17–v18 (gap+trajectory + variance), v19 Path D (empirical credit_age × multiplicative dev penalty), v20 (Gap/Risk Revival with batR-pct + age-sharpening sigmoid riskFactor), v21 (this — power-law). The logistic shape was explored and rejected as too aggressive in the 19→22 window for high-pot prospect ranking. v21 specifically drops devPct because (a) `(cur, pot, age)` are sufficient when pot is the ceiling, and (b) batR-pct actively penalizes high-floor (defense-driven) players. Each pivot documented in `analysis/dev-curve/history.md` (research workspace, outside this repo).

Pipeline outputs (`model/src/export.py`, embedded in `data.meta`):
- `progressCurve.{hit,sp,rp}` — kernel-smoothed median-progress-by-age. **Load-bearing** for the empirical-overlay chart in CurveTuningPanel (parametric `creditAge` plotted against `1 − progressCurve.p50`).
- `devCurve.{hit,sp,rp}` — dev signal unified on **cur-WAR** across all three cohorts (hitter `maxWar.wtd`, SP `sp.wtd.war`, RP **raw** `rp.wtd.war`). Used purely for the Dev% display column on tables — not in the FV formula. (Under WAR the RP distribution is left **unscaled** so it matches the raw RP cur the frontend looks up against it; pre-v21 used batR for hitters, then cur-WAA before the WAR migration.)
- `gapDist.{hit,sp,rp}` — embedded diagnostic. Not used by the FV formula.

### `devPercentileRank(devCurve, age, devValue)`
Player's percentile rank within their age cohort, interpolated from the embedded percentile distribution at the player's exact age. Returns 0..1. **Display only** in v21 (Dev% column).

### `typicalAtAge(devCurve, age)`
Linear-interpolated `p50` lookup. Used by the FVIAT subtext and the empirical reference overlay in CurveTuningPanel.

### `calcFutureValue(cur, pot, age, cs={})`
v21 (power-law creditAge). `cs` keys: `gapMax`, `gapExp`, `maxCurrentAge`. **No `devPct` parameter.**
- `t = clamp((age − 14) / (maxCurrentAge − 14), 0, 1)`
- `gap = max(0, pot − cur)`
- `creditAge = max(0, gapMax × (1 − t^gapExp))`
- `FV = (age ≥ maxCurrentAge) ? cur : (cur > pot) ? cur : cur + gap × creditAge`
- Defaults (`DEV_CURVE_DEFAULTS`): `gapMax=0.80, gapExp=3, maxCurrentAge=27, bandwidth=0.5`.
- Slider ranges (`DEV_CURVE_RANGES`): `gapMax 0.65–1.00 step 0.05`, `gapExp 1–8 step 1`, `maxCurrentAge 26–27`.
- Pre-v21-power saved curveSettings reset on `_version !== "v21-power-v1"`.

### `calcCreditAge(age, cs={})`
Returns the parametric creditAge value at a given age — used by CurveTuningPanel's chart memo to render the parametric curve against the empirical overlay.

### Pool helpers
- `buildBoardPool(data, hitterFilter, pitcherFilter, extraFields)` still stamps `_devPct` per pool entry for the optional display column, but `applySmartRank` calls `calcFutureValue(cur, pot, age, cs)` — no devPct in the formula path.
- `pickPitcherRole(p, devCurves, curveSettings, roleHint)` returns `{role, waa, waaP, waaSort, waaPSort, floorSort, devPct, devCurve, fv}`. `devPct` retained as a metadata field; `fv` is the v21 logistic FV when `curveSettings` provided.
- `pickFielderPos(p, posHint, hitDevCurve, curveSettings)` mirrors the pattern. `hitDevCurve` is no longer needed for FV — kept for the metadata `devPct` field.

### Why power-law `(1 − t^gapExp)`, not logistic
The shipped `creditAge` is the power-law decay `gapMax·(1 − t^gapExp)` — see `calcFutureValue` in `utils/futureValue.js`. A logistic shape with an empirical-anchored midpoint was explored (`analysis/dev-curve/tests/fv_formula_v21_logistic.cjs`) and **rejected** as too aggressive in the 19→22 window for high-pot prospects. Both shapes were R-tested by the harness in `analysis/dev-curve/tests/` (composite of R1/R2/R4/R10/R_curveMatch, plus the hard invariants FV ≥ cur and FV ≤ pot); the power-law `fv_formula_v21.cjs` won. History: `analysis/dev-curve/history.md`.

### Dev% column
Stores `_devPct` (0..1 percentile rank within age cohort, via `devPercentileRank`). Null for matured players (`_age >= maxCurrentAge`). Color via `devPctColor()`; display formatter uses the "Nth" suffix. Shown on Draft Board, IAFA Board, and Org View Overview roster; always computed against the full league pool (`data.hitters`/`data.pitchers`) and always visible (not gated behind the Future Value toggle).

### Dev Analysis Age Binning
Players are binned by integer age using `Math.round()` — age 27.5–28.4 maps to bin 28, age 17.5–18.4 maps to bin 18, etc. Min/max age ranges auto-adjust to whatever is in the dataset (no hardcoded bounds). Age bins with fewer than 3 players are excluded from trend/threshold data. The `ageBins` memo is shared between the gap chart and the avg trend line chart.

### Persisted Curve Settings
Settings persisted to localStorage under `ssb_dev_curve_settings` (versioned via `_version`):
- v21 keys: `gapMax`, `gapExp`, `maxCurrentAge`, `bandwidth`. Two formula knobs exposed as sliders (down from v20's six).
- Read in Dashboard and passed as `curveSettings` prop to DraftBoard, IAFABoard, DevAnalysisView, OrgView, RosterPlanner.
- Boards consume them via `applySmartRank` → `calcFutureValue` for the per-row FV.
- DevAnalysisView uses **local state** for live slider preview; only persists on explicit Save button click.
- Bandwidth drives kernel smoothing for the gap distribution and WAA percentile charts; the embedded `progressCurve` is built at the same default (0.5).
- Migration: any saved blob with `_version !== "v21-power-v1"` is detected and reset to v21 defaults.

### Dev Analysis Performance
The scatter chart (thousands of data points) is wrapped in `React.memo` as `DevScatterChart` to prevent re-renders when curve sliders change. The scatter chart depends on `scatterCurrent`, `scatterPotential`, `minAge`, `maxAge`. Outlier-only tooltips show player name/pos for points outside the 10th-90th percentile band at their age. If adding new heavy visualizations to Dev Analysis, consider similar memoization.

## Data Pipeline
The Python pipeline at `model/` generates `dashboard.json.gz` + uncompressed `dashboard.json` and auto-copies them to `app/public/data/<slug>/` (or `app/public/data/` in legacy single-league mode), then refreshes the `leagues.json` registry via `_update_leagues_index()`. See `model/main.py:247-266` for the copy logic and `model/main.py:66-95` for the registry writer. No manual copy step is required.

## Important Notes
- App.jsx tries `/data/leagues.json` → resolves the active slug → fetches `/data/<slug>/dashboard.json`. If the registry is absent, falls back to legacy `/data/dashboard.json`. If both fail, the app falls back to manual file upload. See **Multi-League Architecture** for full flow.
- localStorage persistence is split: **global** keys (`ssb_current_league`, `ssb_dev_curve_settings`) are shared across all leagues; **per-league** keys (team selection, game date, roster plan + order, R5 threshold, league settings, prospect settings, IAFA signed IDs) are namespaced via `keyFor(slug, baseKey)` → `"baseKey::slug"`. Use `useScopedLocalStorage` (hook) or `readScoped`/`writeScoped` (non-hook) — see **Multi-League Architecture** for the full key mapping.
- All styling is inline (no CSS files) — dark theme with monospace fonts.
- `datedData` in Dashboard is the age-recomputed version of `data` — all views should receive `datedData`, not raw `data`.
- **Always use accessor helpers** (`getWar`, `isEligible`, `resolveKey`, etc.) — never access flat column names like `p["Max WAR wtd"]` directly. WAR accessors are the post-v0.2.0 default; WAA accessors are preserved but unused.
- Heavy pages (`RosterPlanner`, `DevAnalysisView`, `PlayerCompareView`) are `React.lazy`-loaded with a single `<Suspense>` in Dashboard — confirm bundle is split when changing imports.
- Pages can be hidden by missing CSV inputs via `dashMeta.csvPresence` flags (see **CSV Presence & Page Visibility**). Always test with a partial-CSV league before assuming a sidebar item is broken.
